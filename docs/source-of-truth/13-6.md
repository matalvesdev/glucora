13.6 — AI Runtime & Evaluation Blueprint


Status: Implementation Source of Truth


1. Objetivo
Definir a arquitetura implementável de IA preservando os limites de `04 — AI`, `03 — Clinical` e ADR-006/007.


2. Pipeline
Capability request → intent/risk classification → identity/authorization/consent → context builder → deterministic computations → retrieval when needed → model routing → generation → schema validation → safety/policy guard → provenance → response → telemetry/evaluation hooks.


3. Capability registry
Cada capability registra id, intended use, Clinical Risk, input schema, output schema, allowed tools, required corpus, minimum evidence, model routing policy, fallback, eval suite e owner.


4. Model Gateway
Criar interface independente de provider: generateStructured, embed quando necessário, health/status e usage metadata. Provider/model final permanece configuração/versioned bundle e pode ser substituído.


5. Prompt bundle
System instructions, capability prompt, output schema, safety policy, retrieval configuration e model parameters versionados. Mudança relevante é release.


6. Context Builder
Seleciona somente dados autorizados e necessários. Ordena fatos por fonte/fact class/provenance. Nunca converte inference em fact. Long-term memory não é estado oculto do LLM; vem do domínio governado.


7. Retrieval
Corpus allowlisted e versionado. Document metadata inclui source, authority tier, publication/review date, version, jurisdiction/context e approval. Retrieved content é evidência, não instrução executável.


8. Prompt injection defense
Separar instructions de retrieved/user content; tool allowlists; parsing/validation; nunca obedecer instrução encontrada em documento recuperado que tente mudar policy/system/tool permissions.


9. Outputs
Preferir structured outputs. Componentes: observations, evidence refs, context, uncertainty/limitations, low-risk next step quando permitido. Abstain quando grounding/context insuficiente.


10. Tools
Nenhum model recebe SQL/database/admin tool genérico. Tools são capability-specific e server-authorized. Tool calls revalidam actor/purpose/resource.


11. Evals
Golden sets normal/edge/adversarial/abstention/privacy/clinical boundary. Métricas: task correctness, grounding, unsupported claims, citation validity, refusal precision, privacy leakage, cross-user isolation, latency e cost.


12. Safety gates
R0/R1 automated após validação; R2 exige controles/evals adicionais; R3 não entra autonomamente no MVP; R4 fora de escopo.


13. Telemetry
request_id, capability, risk, model/provider/version, bundle version, retrieval ids, validation/guard outcomes, latency, cost/fallback. Não logar raw prompt/response por padrão quando contiver dados sensíveis.


14. Fallback
Deterministic summary/templates ou unavailable-safe state. Falha do LLM não pode bloquear direitos de privacidade, dados canônicos ou funcionalidades básicas.


15. Regra final
A IA recebe contexto e autoridade estritamente necessários para executar uma capability específica; ela nunca recebe autoridade clínica ou de acesso por inferência.
