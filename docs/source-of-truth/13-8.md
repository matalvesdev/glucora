13.8 — MVP Backlog & Implementation Sequence


Status: Implementation Source of Truth


1. Objetivo
Transformar `11.2 — MVP Delivery Plan` em sequência de implementação executável sem confundir prioridade com mera facilidade técnica.


2. Initiative A — Engineering Foundation
A1 monorepo/workspaces; A2 lint/typecheck/test conventions; A3 web shell; A4 Fastify shell; A5 PostgreSQL/migrations; A6 config/env validation; A7 structured logging/request IDs; A8 CI baseline; A9 health/readiness endpoints.
Exit: dev consegue clonar, subir, testar e executar stack local de modo reproduzível.


3. Initiative B — Identity, User & Consent
B1 identity adapter contract; B2 user/profile persistence; B3 session/auth middleware; B4 consent purpose/version model; B5 grant/revoke flows; B6 policy checks; B7 audit events; B8 privacy UI baseline.
Exit: usuário autenticado controla consentimentos e authorization tests passam.


4. Initiative C — Longitudinal Data Core
C1 observation domain; C2 measurement manual capture; C3 context events; C4 provenance; C5 correction/supersession; C6 unit/timezone handling; C7 validation; C8 canonical queries.
Exit: registros criados/corrigidos são temporalmente e semanticamente confiáveis.


5. Initiative D — Timeline
D1 projection builder; D2 chronological API; D3 filters/grouping; D4 source/fact-class presentation; D5 rebuild capability; D6 web timeline UX; D7 empty/missing-data states.
Exit: timeline é útil e reconstruível sem virar source of truth.


6. Initiative E — Consultation Preparation
E1 deterministic summaries; E2 time-range selection; E3 report composition; E4 questions/notes; E5 export artifact; E6 share grant/revoke; E7 audit.
Exit: usuário consegue preparar e levar um histórico compreensível para consulta.


7. Initiative F — Low-risk AI
F1 capability registry; F2 model gateway abstraction; F3 approved corpus/retrieval interface; F4 structured summary/explanation capability; F5 grounding/provenance; F6 guardrails; F7 golden evals; F8 feedback/report flow; F9 safe fallback.
Exit: capability passa eval/safety gates e não executa high-risk clinical decisions.


8. Initiative G — Privacy & User Rights
G1 export request; G2 correction; G3 deletion workflow; G4 consent history; G5 sharing control; G6 contest AI output; G7 status/audit; G8 vendor/deletion hooks.
Exit: direitos essenciais são exercitáveis no produto, não apenas descritos em política.


9. Initiative H — Operational Readiness
H1 monitoring/alerts; H2 backups; H3 restore test; H4 incident/runbooks; H5 support workflow; H6 security scans; H7 threat model; H8 readiness review; H9 private beta rollout.
Exit: Operational Readiness Gate aprovado.


10. Sequência
A → B → C → D → E; F pode começar infraestrutura/evals em paralelo após C, mas só entra em user-facing após contexto/evidence/safety. G inicia junto de B/C e deve estar completo antes de beta. H cresce desde A e fecha antes do beta.


11. Anti-backlog
Fora do MVP: insulin dosing, autonomous diagnosis, treatment change, emergency diagnosis, marketplace, full Pro workspace, every CGM integration, native mobile obrigatório, Kafka/Kubernetes/microservices, social gamification.


12. Story template
Problem/Job; scope; domain; risk; acceptance criteria; data/privacy impact; clinical/AI classification; observability; tests; docs/ADR impact; Definition of Done.


13. Regra final
Backlog existe para provar o ciclo de valor seguro do MVP — não para acumular funcionalidades.
