11.2 — MVP Delivery Plan


Status: Source of Truth — Roadmap


1. Objetivo
Traduzir o MVP definido em `02.10 — MVP Definition` em uma sequência de entrega técnica, clínica, de dados e operacional que produza valor utilizável sem expandir escopo prematuramente.


2. Princípio
O MVP não é a menor quantidade de código; é a menor capacidade completa capaz de produzir um Useful Understanding Cycle de forma segura, auditável e operável.


3. Trilha A — Product Foundation
Auth; profile; consent; privacy settings; accessibility baseline; analytics mínimos; feature flags; support entry points.


4. Trilha B — Data Foundation
Canonical longitudinal model; selected manual capture; timestamps/units; provenance; corrections; data quality states; timeline projection; export/delete foundations.


5. Trilha C — Core Experience
Timeline; contextual organization; summaries; consultation preparation; structured share/export; feedback/correction flows.


6. Trilha D — Low-Risk Intelligence
Deterministic aggregation primeiro; descriptive patterns; approved educational context; RAG quando necessário; provenance; uncertainty/limitations; safe fallback.


7. Trilha E — Clinical & Compliance
Intended use baseline; risk classification; claims register; clinical content review; LGPD map; consent model; RIPD where triggered; incident/escalation flows; safety evals.


8. Trilha F — Platform Operations
CI/CD; production environments; observability; backup/restore; incident management; runbooks; security operations; customer support; operational readiness gate.


9. Sequência sugerida
Foundation → canonical data → capture → timeline → summary/report → intelligence → sharing/export → hardening → controlled pilot.
Parallelizar apenas quando contracts e dependencies estiverem claros.


10. Alpha interno
Objetivo: provar fluxos e arquitetura com synthetic/non-sensitive test data. Critérios: core flow funcional, migrations, observability, access controls, basic security/testing.


11. Private beta
Pequena população autorizada, suporte próximo, low-risk outputs apenas, telemetry e qualitative research. Critérios: safety/compliance gates, export/delete, incident readiness, support and rollback.


12. MVP release
Exposição ampliada somente após sinais de value, acceptable reliability, safety, privacy, supportability e operational readiness.


13. Fora do MVP
Autonomous diagnosis/treatment; insulin dose changes; emergency monitoring; high-risk prediction; full Pro; payer population analytics; native apps unless blocker; broad device ecosystem; marketplace; complex gamification.


14. Scope control
Novo item entra no MVP somente se resolver blocker de user value, safety, compliance, operability ou critical learning. Todo o restante compete pelo pós-MVP.


15. Definition of MVP Done
Um usuário elegível consegue registrar/importar contexto permitido, visualizar histórico, obter entendimento descritivo de baixo risco, preparar/compartilhar consulta, corrigir dados, exercer direitos básicos e receber suporte — com provenance, segurança, observabilidade e fallback.


16. Regra final
O MVP termina quando o loop de valor funciona de ponta a ponta em produção controlada, não quando uma lista de telas está implementada.
