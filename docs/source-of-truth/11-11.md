11.11 — Phase Definition of Done


Status: Source of Truth — Roadmap


1. Objetivo
Definir quando cada fase pode ser considerada concluída sem confundir activity completion com outcome/evidence completion.


2. Fase 0 — Foundation & Validation Done
Source of Truth coerente; ICP/problem/JTBD validados o suficiente; major assumptions registrados; intended use/boundaries definidos; data/regulatory feasibility sem blocker desconhecido crítico; implementation hypothesis aprovada.


3. Fase 1 — MVP Consumer Done
Core loop funciona end-to-end em produção controlada; privacy/data rights operáveis; low-risk outputs aprovados; observability/support/incident/backup ready; users alcançam value moment; major safety failures ausentes ou mitigados.


4. Fase 2 — Context Expansion & Paid Validation Done
Selected integrations/context melhoram utility; retention signal melhora ou permanece saudável; willingness-to-pay evidence existe; pricing/package hypotheses testadas; economics observáveis; support/integration cost conhecido.


5. Fase 3 — Pro Pilot Done
Professional workflow usado de verdade; patient authorization funciona; utility/efficiency signal; no role ambiguity material; clinical/privacy gates passaram; pilot implementation repetível o suficiente.


6. Fase 4 — B2B2C Pilot Done
Enrollment/account operations, reporting boundaries, privacy firewall, contracts, support e implementation funcionam; buyer/user value evidenciado; economics e renewal signal mensuráveis.


7. Fase 5 — Platform Done
Public contracts versionados; partner auth/webhooks/docs/support; at least repeated external demand; stable internal capabilities; partner onboarding operável; platform economics observáveis.


8. Fase 6 — Advanced Clinical Intelligence Done
Somente quando intended use, regulatory status, evidence, validation, human oversight, monitoring, quality system e incident obligations estiverem adequados à risk class real.


9. Cross-functional DoD
Toda fase exige documentação atualizada, decisions registradas, metrics definidas, risks reviewed, owners definidos, operational readiness e lessons incorporated.


10. Technical completion ≠ phase completion
Código shipped é apenas um componente. Uma fase não está done se valor, safety, compliance, operations ou evidence não foram demonstrados.


11. Regra final
Done significa capacidade sustentável + aprendizado suficiente para justificar a próxima responsabilidade.
