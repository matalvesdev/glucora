13.7 — CI/CD, Testing & Observability Blueprint


Status: Implementation Source of Truth


1. Objetivo
Definir o mínimo operacional para entregar mudanças com segurança e detectar regressões rapidamente.


2. Pipeline PR
Install/cache → lint/format check → TypeScript typecheck → unit tests → contract/schema tests → integration tests → security/dependency/secret scanning → build web/api → test artifacts. E2E seletivo para critical paths.


3. Main/release
Após merge: build immutable artifacts, migrations validation, environment deployment, smoke tests e post-deploy monitoring. Production promotion pode requerer manual approval enquanto maturidade for baixa.


4. Test pyramid
Unit: domínio e application services.
Integration: PostgreSQL/adapters/auth policies/integration parsing.
Contract: OpenAPI, schemas e provider adapters.
E2E: signup/consent → capture → timeline → consultation report → export/share/privacy critical flows.
AI evals: pipeline separado mas obrigatório para bundles/capabilities afetados.


5. Critical test suites
Consent/revocation; authorization matrix; observation versioning; provenance; deduplication/idempotency; timeline projection rebuild; deletion/export; sharing revocation; AI boundary/refusal; audit generation.


6. Test data
Synthetic fixtures por default. Nunca copiar production health data para CI/dev. De-identification não é desculpa para uso casual de dataset real.


7. Observability
Structured logs + metrics + traces com request_id/correlation_id. Stack/provider permanece ADR aberto. Abstração deve evitar vendor lock-in excessivo.


8. Core technical signals
Request rate/errors/latency; DB pool/query health; job queues; import success/failure; auth failures; API dependency health; build/deploy health.


9. Product/safety operational signals
First-value failures, timeline/report generation failures, AI guard blocks, unsafe-output reports, consent/privacy workflow failures e sharing errors.


10. Sensitive telemetry
Não enviar measurement values, medication details, prompts/responses ou free-text health notes como tags/log attributes por padrão.


11. Deployment
Feature flags para high-risk changes quando apropriado. Migrations before/compatible-with code strategy. Rollback/forward-fix explicit.


12. Dependency policy
Lockfiles committed; automated update tooling permitido; upgrades passam testes. Critical runtime dependencies mantidas pequenas e justificadas.


13. Supply chain
Pin Actions/tool versions quando possível; least-privilege CI permissions; no secrets in forks/untrusted workflows; build provenance/SBOM conforme maturidade/enterprise need.


14. Quality gates
Nenhum merge com failing required checks. Override emergencial documentado e seguido por corrective action.


15. Regra final
CI/CD não serve apenas para publicar software; é o primeiro sistema automatizado de evidência de que a Glucora continua dentro dos contratos aprovados.
